# نظام إدارة أسطول نبع الطاقة — نسخة تجريبية كتطبيق ديسكتوب (Tauri)

هذا مشروع تجريبي (Proof of Concept) يُحوِّل نظام الأسطول من صفحة ويب (ملف HTML واحد) إلى **تطبيق ديسكتوب حقيقي مُثبَّت** — بدون أي تغيير فى منطق البرنامج أو ميزاته: نفس ملف `src/index.html` بالضبط هو نظام الأسطول الأصلي، فقط مُغلَّف الآن داخل نافذة برنامج حقيقية باستخدام إطار عمل Tauri (مفتوح المصدر ومجاني).

## ما الذى أثبتناه فعليًا (فى بيئة لينكس تجريبية)
- تم بناء التطبيق فعليًا وتشغيله، وظهرت واجهة النظام الكاملة بشكل صحيح 100% (لوحة المعلومات، البيانات الحقيقية، شارة "النظام سليم").
- تم التأكد أن التطبيق يحفظ بياناته فى **مجلد واحد ثابت** على القرص (مرتبط بهوية التطبيق نفسه: `com.nabaaltaqah.fleet`) — **وليس بمسار الملف كما يحدث فى المتصفح**. هذا يعنى نظريًا حل مشكلة "كل نسخة جديدة = بيانات فارغة" جذريًا، لأنه لا يوجد بعد الآن "نسخ متعددة" — تطبيق واحد مُثبَّت، يُفتَح دائمًا من نفس المكان.

## ملاحظة هامة يجب التحقق منها على ويندوز تحديدًا
أثناء الاختبار على لينكس، لاحظنا أن حفظ أكبر جزء من البيانات (حالة النظام الرئيسية) لم يظهر فى ملف التخزين كما هو متوقَّع، بينما نجحت أجزاء أصغر (سجل النسخ الاحتياطية، بيانات المزامنة). هذا على الأرجح خاص بمحرك الويب المستخدَم على لينكس تحديدًا (WebKitGTK) وليس مشكلة فى الكود نفسه — على ويندوز سيستخدم Tauri محرك WebView2 (نفس محرك Edge/Chrome، سعة تخزين أكبر بكثير عادةً)، لكن **يجب التحقق من هذه النقطة عمليًا بعد أول بناء حقيقي على ويندوز** قبل الاعتماد الكامل على هذا الأسلوب.

## لماذا لم يُبنَ ملف exe/msi جاهز مباشرة هنا
بيئة العمل السحابية المستخدَمة لبناء هذا المشروع مسموح لها بالاتصال بعدد محدود من الخوادم فقط لأسباب أمنية، وخادم توزيع أدوات "Rust" الرسمي (المطلوب لتجهيز البناء الموجَّه لويندوز تحديدًا) غير متاح ضمن هذه القائمة. لذلك تم بناء واختبار التطبيق بنجاح كامل على لينكس فقط (لإثبات أن الفكرة تعمل تقنيًا). ملف exe/msi الفعلي لويندوز يحتاج بناءه إما تلقائيًا عبر GitHub (الطريقة (أ) أدناه — **موصى بها، بدون أي أوامر أو برمجة**)، أو يدويًا على جهاز ويندوز حقيقي (الطريقة (ب)).

## الطريقة (أ) — بناء تلقائي بالكامل عبر GitHub (موصى بها، بدون تثبيت أي برنامج، 5 دقائق مرة واحدة فقط)

هذا المشروع يحتوي بالفعل على ملف جاهز (`.github/workflows/build-windows.yml`) يجعل GitHub (خدمة مجانية) تبني ملف التثبيت لويندوز **تلقائيًا بالكامل** بمجرد رفع الملفات — بدون كتابة أي أمر أو تثبيت أي برنامج على جهازك.

1. افتح [github.com](https://github.com) وأنشئ حسابًا مجانيًا (لو ماعندكش بالفعل) — بريد إلكتروني وكلمة مرور فقط، دقيقتين.
2. اضغط "+" أعلى الصفحة → "New repository". اختر أي اسم (مثلاً `fleet-desktop`)، اتركه "Private" أو "Public" حسب رغبتك، ثم "Create repository".
3. فى صفحة المستودع الفارغ، اضغط "uploading an existing file" (أو "Add file" → "Upload files").
4. من جهازك، افتح مجلد المشروع اللي وصلك (بعد فك الضغط عن الملف المضغوط)، **حدد كل المحتويات جوه مجلد `fleet-desktop` واسحبها** لصفحة الرفع فى المتصفح (تأكد إن مجلد `.github` المخفي انسحب معاها أيضًا — لو المتصفح ما وضحوش، جرّب سحب المجلد `fleet-desktop` نفسه دفعة واحدة بدل محتوياته).
5. اضغط "Commit changes" أسفل الصفحة.
6. اذهب لتبويب "Actions" أعلى صفحة المستودع — هتلاقي عملية بناء ("Build Windows Installer") بدأت تلقائيًا (دائرة صفراء دوارة). انتظر 3-6 دقائق تقريبًا حتى تتحول لعلامة ✅ خضراء.
7. اضغط على اسم العملية المكتملة، وفى أسفل الصفحة هتلاقي قسم "Artifacts" — حمّل الملف المضغوط الظاهر هناك (اسمه "نظام-اسطول-نبع-الطاقة-ويندوز"). بداخله ملف `.exe` و/أو `.msi` — هو ملف التثبيت النهائي الجاهز لويندوز.
8. انسخ هذا الملف لجهاز الكمبيوتر فى الشغل (أو أي جهاز ويندوز تريد)، وشغّله مرة واحدة للتثبيت — بعدها يصبح برنامجًا عاديًا فى قائمة "ابدأ" باسم "نظام إدارة أسطول نبع الطاقة".

**لأي تحديث مستقبلي**: يكفي تكرار الخطوة 4 برفع الملفات المحدَّثة فقط (استبدال القديم)، وستتكرر خطوات 6-8 تلقائيًا فى كل مرة.

## الطريقة (ب) — بناء يدوي على جهاز ويندوز مباشرة (بديل، يحتاج تثبيت أدوات المطورين)
1. تثبيت [Node.js](https://nodejs.org) (النسخة LTS).
2. تثبيت [Rust](https://www.rust-lang.org/tools/install) (`rustup-init.exe` من الموقع الرسمي).
3. تثبيت "Microsoft C++ Build Tools" (يظهر رابطها تلقائيًا أثناء تثبيت Rust على ويندوز إن لم تكن مثبَّتة أصلًا — مطلوبة للبناء على ويندوز فقط).
4. فتح "موجّه الأوامر" (Command Prompt) داخل مجلد المشروع هذا، وتنفيذ:
   ```
   npm install
   npm run tauri build
   ```
5. بعد انتهاء البناء (قد يأخذ عدة دقائق أول مرة)، يظهر ملف التثبيت الجاهز داخل:
   `src-tauri/target/release/bundle/nsis/` (ملف `.exe` مثبِّت) أو `src-tauri/target/release/bundle/msi/` (ملف `.msi`).
6. تشغيل ملف التثبيت هذا مرة واحدة على أي جهاز ويندوز يُراد تشغيل النظام عليه — بعدها يصبح برنامجًا عاديًا فى قائمة "ابدأ".

2. تم الاكتفاء ببناء ملف `.exe` عبر أداة NSIS فقط (أكثر استقرارًا مع العربى)، وإلغاء الاعتماد على WiX/`.msi` نهائيًا لتقليل احتمالات الفشل.

بعد رفع هذا الإصدار المُحدَّث لنفس المستودع على GitHub (بنفس خطوات GitHub Desktop السابقة: نسخ الملفات الجديدة فوق القديمة → Commit → Push)، سيعمل البناء تلقائيًا من جديد، والمتوقع نجاحه هذه المرة.
